# v1.0.0 Performance & Security Report — 2026-07-12

## Performance benchmark

Reproduce: `python scripts/perf_bench.py 10000` (10,000 memories across 20
agents, 5 teams, 5 projects; visibility split global / team / project). Machine:
Apple Silicon, Python 3.12, SQLite WAL.

| Operation | p50 | max | Notes |
|---|---|---|---|
| `add` (per memory) | **0.17 ms** | — | ~6,000 writes/s incl. FTS + auto-index |
| `search` (ACL-gated) | **<1 ms** | 58 ms (cold) | FTS5 candidate + ACL rejoin; cold query warms caches |
| `orchestrate_context` | **7.8 ms** | 76 ms | budgeted multi-section pack |
| `usage_summary` (4 cards) | 103 ms | 104 ms | full O(n) scan — dashboard endpoint, not a hot path |
| `maintenance_scan` | 105 ms | 105 ms | full orphan scan — ops endpoint |
| `export_bundle` (10k) | 126 ms | — | whole-store bundle |
| `import_bundle` (10k) | 647 ms | — | LWW merge + ACL clock + FTS reindex |

Integrity holds at 10k. **Conclusion:** interactive paths (add/search/pack) are
well within interactive latency at 10k memories. The two ~100 ms operations
(`usage_summary`, `maintenance_scan`) are dashboard/ops endpoints that scan the
whole store in Python; acceptable for v1.0, and both are candidates for a cached
or SQL-side aggregation if a deployment grows past ~10⁵ memories.

## Security testing

The security posture is enforced and covered by regression tests (run
`pytest tests/test_review_fixes_v0_14.py tests/test_resilience.py
tests/test_webui_batch.py tests/test_federation_trust.py`):

**Authentication / authorization**
- Full-token gate on every `/api/` route (`hmac.compare_digest`); `/health`,
  `/healthz`, `/metrics` intentionally open (no sensitive data).
- Read-only token tier: authorizes GET/HEAD/OPTIONS only; every mutation verb
  requires the full token (`test_readonly_token_allows_get_blocks_mutation`).
- Destructive ops gated by an explicit confirm token (`orphans/delete`,
  `update-run`, `purge_owner`).

**Federation trust (the v0.14-review core)**
- Org-structure mutations are authorized against the peer's policy scope; an
  anonymous push cannot forge membership or delete teams
  (`test_untrusted_push_cannot_forge_membership`, `test_untrusted_org_tombstone_cannot_wipe_team`).
- Future-dated org/ACL timestamps are rejected (`test_future_dated_org_record_rejected`).
- Revocation propagates via the ACL clock and only ever *reduces* visibility on
  import — an older incoming ACL never re-grants access
  (`test_older_acl_change_does_not_clobber_newer_local`).

**Input hardening**
- Malformed bundles roll back atomically; garbage `members` fields are coerced,
  not iterated into per-character members; oversized/unicode content imports
  cleanly (`tests/test_resilience.py`).

**Self-updater**
- The console restarts only the pid + argv it recorded in `<home>/web.pid`
  (never a `ps`-derived command), closing the local code-execution vector.

**Data exposure**
- `/metrics` and `/api/usage` expose aggregate counts only — no content, ids, or
  secrets. `shared` peers receive no org membership graph; project-scoped exports
  narrow the parent-team roster to project members.

No HIGH or MEDIUM findings remained open after the final review pass (see the
companion review below).
