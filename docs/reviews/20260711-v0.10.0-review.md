# Code Review & Security Review — Agent Memory OS v0.10.0

Date: 2026-07-11 · Reviewed range: `d6b8539..HEAD` (v0.2.3 → v0.10.0, ~40
commits, ~6k changed lines) · Method: six independent review agents run in
parallel — three security (web layer, ACL/data core, federation/service/config)
and three correctness (db core, client/orchestrator, sync/service/cli/mcp) —
followed by manual verification of every high-confidence finding against the
source, targeted fixes, and a full re-run of the test suite and validation
harness.

This is the first full review since the v0.2.x web-rework review; everything
added since (context orchestration, retention, federation mesh, agent
registry/team ACL, adaptive forgetting, auto semantic index, i18n console,
service install, token gate) was in scope.

## Verdict

**Ship-ready after this pass, with a federation-hardening workstream to
schedule.** No remotely-exploitable memory-content leak survives against the
system's own trust model: the private-memory isolation invariant holds through
search, resonance, orchestrate, graph, and now the single-memory/links web
endpoints. Twelve concrete bugs were fixed and pinned with regression tests
(195 tests pass, up from 184; validation harness still PASS). Fifteen further
findings are genuine but are design decisions or scoped changes that should not
be made silently mid-review; they are catalogued below with recommendations.

The single most important theme for the next milestone is the **federation
trust model**: peer sync currently treats a registered peer as a full-trust
replica of the entire store. That is a coherent design, but it is not the
selective/team-scoped sharing the docstrings imply, and it deserves an explicit
decision (see D1–D4).

## Fixed in this pass

Each fix has a regression test in `tests/test_review_fixes_v0_10.py` unless
noted.

### Security

**S1 · MCP identity override (High)** — `mcp_server.py`
`memory_orchestrate_context` and `memory_recall_feedback` exposed a
caller-supplied `requester_agent_id` that overrode the env-pinned
`AGENT_MEMORY_AGENT_ID`. In the MCP model an agent's identity is fixed by its
environment, not chosen per call, so this let an agent read another identity's
private context (orchestrate) or weaken/reinforce memories it cannot see
(feedback) — the exact case `_recall_eligible_ids` exists to block. The
sibling tools (`memory_search`, `memory_context_pack`) already hardcoded the
env identity, confirming the override was unintended. **Fix:** removed the
parameter from both tools; identity is always the env agent.

**S2 · Web single-memory / links endpoints bypassed the ACL gate (Medium)** —
`web_app.py` `GET /api/memories/{id}` and `GET /api/memories/{id}/links` went
through `client.get()` / `client.links()`, which apply no visibility filter,
unlike `/api/search`. **Fix:** added `MemoryStore.get_visible()` /
`MemoryClient.get_visible()` (the same `_visible_rows_for_ids` hard gate every
other track uses), threaded `requester_agent_id`/`requester_team_id` through
both endpoints, and made the console pass its `actingAs()` selector.
*Severity note:* the web layer's requester is caller-supplied by design (a
requester-less call is the documented operator/admin view, identical to
`/api/search`), so this is a consistency-and-correctness fix, not a token-holder
privilege escalation. It closes the gap where a **well-behaved** requester
still saw other agents' private content through these two routes.

### Correctness & data integrity

**C1 · `purge_owner` left the cold archive and side tables intact (High,
data-loss/privacy)** — `db.py`. The right-to-forget / agent-retirement
operation deleted from `memories`, `memory_links`, and `recall_profiles` but
not `memories_archive`, `session_recall_log`, or `memory_audit`. Any of the
owner's memories already moved to cold archive by retention survived and were
resurrectable via `restore_archived`. **Fix:** collect the owner's ids across
active + archive, delete archive rows and id-keyed log/audit rows, and return
an `archived_deleted` count.

**C2 · `resonance_search` crashed on any seed (High)** — `client.py:631`
built `{res.id: res}` over `SearchResult` objects, which have no `id`
(line 618 correctly uses `res.record.id`). The method raised `AttributeError`
whenever it found a seed and only "worked" when it found nothing. Orphaned
(no callers/tests), but public on the facade. **Fix:** `res.record.id`.

**C3 · LLM link extractor crashed consolidation on a non-string reply
(Medium)** — `extractors.py`. Only the `complete()` call was inside the
"must never break consolidation" try/except; `_parse_pairs(reply, …)` ran
outside it, so a `None` reply (a common LLM-client error convention) raised
`TypeError` in `re.search`. **Fix:** guard the reply type and move parsing
inside the try.

**C4 · `agents.toml` `teams = "apollo"` silently mis-registered (Medium)** —
`agents_config.py` did `[str(t) for t in teams]`, iterating a string
character-by-character into single-letter teams (`["a","l","o","p"]`), silently
denying the agent every real team ACL. **Fix:** reject a non-list `teams` with
a clear error.

**C5 · Malformed `agents.toml` half-registered the fleet and bricked every
client (Medium)** — `agents_config.py` upserted (and committed) agents
one-by-one, so an invalid entry mid-file left earlier agents applied and made
every `MemoryClient` open raise. **Fix:** validate all entries (id, kind) up
front, then apply — one bad entry aborts before any write.

**C6 · Share/revoke reset the freshness & decay clock (Medium, ranking)** —
`db.py`. `share_memory`/`revoke_share` routed a pure ACL change through
`update_memory`, bumping `updated_at`; a stale 300-day-old note jumped back to
freshness 1.0 and to the top of every agent's results just by being shared, and
its decayed-archival clock restarted. Same class as the already-fixed
`helpful=False` bug. **Fix:** new `_set_visibility()` updates only the
`visibility` column, leaving `updated_at` untouched.

**C7 · Stale auto semantic index after an in-place edit (Medium)** — `db.py`
`semantic_signature` was `(count, max(rowid), max(updated_at))` at second
granularity, so an in-place content edit whose `updated_at` fell in the current
max second left the signature unchanged and `AutoSemanticIndex` kept serving
the old embedding. **Fix:** add a `SUM(LENGTH(content))` / `SUM(LENGTH(summary))`
term — content edits change it, reinforcement writes (which never touch
content) do not, so there is no spurious rebuild. Both directions are tested.

**C8 · `rotate_snapshots` archived pinned snapshots (Medium)** — `db.py` the
ROW_NUMBER window never excluded `pinned`, violating retention's invariant that
only a hard expiry retires a pinned row. **Fix:** `AND pinned = 0`.

**C9 · `import_bundle` never rolled back a partial merge (Medium,
data-integrity)** — `sync.py`. A truncated/corrupt bundle line raised mid-loop
with prior INSERT/UPDATEs uncommitted on the shared connection; the next
unrelated `commit()` (e.g. `record_peer_sync`) then persisted the half-merge.
**Fix:** wrap the merge in try/except with `rollback()` on any error.

**C10 · Bundle temp files crashed on non-ASCII on Windows (Medium)** —
`sync.py` (×2) and `web_app.py` (×2) wrote bundles to a text-mode
`NamedTemporaryFile` without `encoding="utf-8"`; bundles are exported with
`ensure_ascii=False`, so any CJK/accented content raised `UnicodeEncodeError`
under the Windows locale codec. **Fix:** `encoding="utf-8"` on every temp write.

### Federation trust model (schedule as one workstream)

> **Update — resolved in v0.11.0.** D1–D4 were taken up as the federation-trust
> milestone (migration 9): per-peer `shared`/`full`/`team:<id>` policy with
> private-safe defaults, HTTP export always `shared`-scoped, tombstone
> propagation, import provenance + anti-impersonation, and convergent
> normalized-timestamp LWW. See CHANGELOG [0.11.0] and `SPEC.md`. The findings
> below are kept for the record.

**D1 · Peer sync ships the entire private store (High, design)** —
`push_to_peer` / `sync_all_peers` / `GET /api/sync/export` call `export_bundle`
with `team=None`, exporting **all** memories including every agent's private
ones. The ACL travels with each row (a private memory stays owner-only on the
peer), so this is not an in-app leak — but the raw content leaves the local
trust boundary to the peer's disk, and there is no way to do a team-scoped
*peer* sync (team scoping exists only for manual CLI file export). Decide: (a)
scope peer sync by team/policy, or (b) explicitly document peers as a full-trust
replication domain. Recommend (a) with a per-peer visibility policy.

**D2 · `import_bundle` trusts peer-supplied `owner`/`visibility` verbatim
(Medium, design)** — a malicious/compromised peer can craft a bundle memory
with `owner` = a local agent and `visibility = ["global"]`, which then surfaces
to all local agents under a forged trusted identity (false-fact / prompt-
injection vector). Recommend namespacing imported provenance or quarantining
cross-owner writes. (Link-bridging into resonance is *not* exploitable —
`_visible_rows_for_ids` re-applies the ACL per hop and ids are `mem_`+uuid4.)

**D3 · No tombstones — deletions resurrect (Medium, data-integrity)** — a
memory deleted or retention-archived on one node is re-inserted from any peer
that still has it, so forgetting never converges across a mesh. Recommend a
synced tombstone table.

**D4 · Last-writer-wins timestamp fragility (Medium)** — LWW uses strict `>`
on second-precision ISO strings: same-second concurrent edits never converge in
either direction, and a mixed `Z` vs `+00:00` suffix compares wrong
lexicographically. Recommend normalizing the timestamp format and adding a
stable id tie-break.

### Ranking & lifecycle

**D5 · Authority-track fusion double-applies metadata (Medium, ranking)** —
`db.py` feeds the FTS result's already-`effective_score`d value back into
`_score_row` as `text_score`, so importance/confidence/freshness multiply
twice on authority hits. Recommend fusing raw text relevance. *Deferred
because changing scoring requires a fresh validation pass.*

**D6 · `tune_decay_from_feedback` clobbers explicit half-lives (Medium)** —
it recomputes from the per-type default base, overwriting a
`decay_half_life_days` the user set at creation or via `update_memory`.
Recommend auto-tuning only records still on the type default.

**D7 · Archived memories lose their graph (Medium, data-loss)** —
`_archive_where` hard-deletes links and the archive stores no edges, so
`restore_archived` returns a memory with degree 0. Recommend archiving edges
alongside and restoring both.

**D14 · `record_recall` co-links contradicting memories (Low)** — with
`create_colinks=True`, a pair joined only by `supersedes` gets a parallel
`co_recalled` edge (the supersedes-exclusion makes the UPDATE match 0 rows),
re-associating a superseded memory and double-counting it in resonance.
Recommend skipping the colink when the only existing edge is `supersedes`.

### Concurrency, privacy, orchestration

**D8 · `_teams_cache` never expires across processes (Medium)** — a
long-running server caches team memberships; a membership change via a separate
CLI process is never seen until restart, granting stale visibility (or hiding
new grants). Recommend a TTL or mtime-based invalidation. (Single-process
invalidation is correct.)

**D9 · `/api/sync/run` holds the app lock across peer HTTP (Medium)** — the
app-wide client lock is held through 30s-timeout peer round-trips, freezing
every other endpoint; a self-referential peer deadlocks until timeout.
Recommend doing HTTP outside the lock.

**D10 · De-identified share leaks owner via audit (Medium, privacy)** —
`share_memory(deidentify=True)` writes an audit row on the copy with
`actor` = the original owner, and `audit_log` is not ACL-gated, so a recipient
can recover the owner; copy `tags` are also carried over verbatim. Recommend
scrubbing the copy's audit actor/tags and gating `audit_log`.

**D11 · Orchestrator can drop the top hit entirely (Medium)** — records are
added to `placed` before budget trimming, so a hit dropped by one section's cap
is also excluded from the task section that had room for it. Recommend marking
`placed` only on actual emit.

**D12 · Token estimate undercounts CJK ~4-6× (Medium)** — `(len+3)//4` means
an orchestrated pack reporting `used_tokens <= max_tokens` can be several times
over budget on Japanese/Chinese content (the console ships five languages).
Recommend a CJK-aware estimate.

**D13 · Token file has a world-readable window (Low)** — `save_token` writes
with default umask before `chmod(0o600)`; on a shared host another user can read
the token in between, and concurrent rotate is non-atomic. Recommend
`os.open(..., 0o600)` / atomic replace.

**D15 · `agents.toml` re-apply wipes console-set metadata (Low)** — re-apply
resets `display_name`/`notes`/`kind` a file entry doesn't mention. Partly by
design ("file is authoritative"); recommend overwriting only the fields an
entry actually specifies.

## Checked and cleared (no vulnerability)

- **SQL injection:** FTS5 `MATCH` input is bound as a parameter with quotes
  stripped; all dynamic SQL uses `?` placeholders — no user-controlled column
  or `ORDER BY` interpolation anywhere in the new code (archive, dashboard,
  consolidate, graph, agents, peers).
- **Resonance non-traversal:** invisible nodes are both unreturnable and
  untraversable — traversal re-seeds only from `_visible_rows_for_ids`.
- **Team-scoped export boundary:** `export_bundle(team=…)` correctly restricts
  to `team:<id>` / `team`+`source.team_id` and keeps only in-bundle links.
- **XSS:** the console renders via `textContent` / DOM-API element creation;
  `innerHTML` is used only to clear. i18n strings are static, not interpolated
  into HTML.
- **Token gate:** `hmac.compare_digest` (constant-time); token is never logged,
  echoed, or placed in a URL; page shell + `/health` are the only unauthenticated
  paths; no CORS middleware (bearer-header model, so no CSRF).
- **Peer transport:** rejects non-`http(s)` URLs, uses urllib's default
  cert-verifying TLS context (no verification disabled anywhere), and sends the
  peer token only to that peer's URL.
- **Service install:** `subprocess.run` with list args (no `shell=True`); plist/
  unit/schtasks content embeds only trusted local paths, never the web token.
- **Deserialization:** turbovec/embedding build indexes in-memory from local
  SQLite; no `pickle`/`np.load(allow_pickle=…)` of any synced or imported
  artifact.
